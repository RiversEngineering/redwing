Redwing Quick Reference: PID Position Control

PID position control turns a DC motor + encoder into a servo you can trust: you give it a target encoder count, and the Pico drives the motor there and holds it, pushing back if something knocks it away. Unlike a servo, you can always read where it really is with enc.count.

Setup (before robot.start())

arm = robot.D0.motor()
enc = robot.D2.encoder()
arm.attach_encoder(enc)      # PID needs to know which encoder belongs to this motor
arm.set_pid(10, 0, 0.5)      # KP, KI, KD

Wire the encoder so enc.count goes up when the motor has positive power (use enc.invert() if it doesn't). If they disagree, PID pushes the wrong way and the arm runs away to the end of its travel.

Moving (after robot.start())

arm.go_to_position(500)                # drive to tick 500 and HOLD there
arm.go_to_position(0, max_speed=40)    # same, but never above 40% power
arm.move_by(100)                       # 100 ticks further from where it is now
arm.move_by(-100)                      # 100 ticks back

enc.count                              # where the arm actually is right now
arm.stop()                             # turn PID off (motor goes limp!)

These commands return right away; the Pico does the moving in the background. Your loop keeps running, and the arm keeps holding its target until you give it a new one. Calling arm.set_power() or arm.stop() turns PID off, so an arm will drop.

Where is zero?

Targets are measured from wherever the encoder was last zeroed: when the program starts, or when you call enc.reset(). Always start with the arm in the same spot (e.g. resting down against its stop) so 0 means the same thing every run.

Ticks → degrees

TICKS_PER_DEG = 1425.1 / 360    # encoder ticks per ARM revolution / 360

arm.go_to_position(90 * TICKS_PER_DEG)    # raise the arm to 90°

angle = enc.count / TICKS_PER_DEG         # where the arm is, in degrees

Find TICKS_PER_DEG yourself: reset() the encoder, move the arm by hand from straight down to straight up (180°), read enc.count, and divide by 180. Gears and chains between the motor and the arm change this number.

Tuning the gains

set_pid(KP, KI, KD) uses % power per tick of error. With KP = 10, the arm gets full power when it's 10+ ticks from its target.

  • KP (push): start at 10. Too low → slow, stops short of the target. Too high → overshoots and wobbles.
  • KD (brake): start at 0.5. Raise it to calm overshoot and wobble near the target.
  • KI (patience): start at 0. If gravity makes the arm sag a little below its target, try a small value with a cap: and cap it with integral_max (below).

Use robot.plot() on the target and position to see what the arm is doing while you tune.

Capping KI: integral_max

KI works by adding up the error over time, so the longer the arm is off target, the harder KI pushes. If the arm is stuck (blocked by a hand or a hard stop, or just slow to get there), that sum keeps growing. This is called integral windup. When the arm finally gets free, all that stored-up push makes it shoot past its target before KI can unwind.

integral_max puts a ceiling on the sum, so KI can never add more than KI × integral_max % power:

arm.set_pid(10, 0.5, 0.5, integral_max=40)    # KI can add at most 0.5 × 40 = 20% power

Pick it backwards: decide the most power KI should ever add (enough to hold the arm up against gravity, say 20%), then integral_max = that % ÷ KI. Leave it out and there's no cap.

Keeping KI: keep_integral

Each go_to_position() call normally restarts KI from zero. That's right for jumping to a new position, but not when your code sends a new target every loop (e.g. a joystick nudging the arm). Then KI never gets time to build up and fight gravity. Pass keep_integral=True so KI carries over between calls:

target = target + gp.left_y * 2          # joystick nudges the target a little every loop
arm.go_to_position(target, keep_integral=True)

Always set integral_max in set_pid() when you use this. Without a cap, KI built up holding the arm in one direction can push against you for a moment when you reverse.

Stop the buzzing: deadband

Gears and chains have a little slop (backlash). The arm can end up hunting back and forth by a few ticks around its target, buzzing and never settling. A deadband tells PID: inside ±N ticks of the target, you're close enough, so stop pushing.

arm.set_position_options(deadband=5)     # setup: "close enough" = within 5 ticks

Inside the deadband the motor output is 0 and KI is frozen. Start around 3–5 ticks. Too big, and the arm stops noticeably short of the target or sags under its own weight before PID pushes back.

Example: arm with three preset positions

from redwing import Robot

TICKS_PER_DEG = 1425.1 / 360    # measure this on YOUR arm

robot = Robot()
arm   = robot.D0.motor()
enc   = robot.D2.encoder()
gp    = robot.gamepad
arm.attach_encoder(enc)
arm.set_pid(10, 0, 0.5)
robot.start()

enc.reset()                  # start with the arm resting DOWN: that spot is 0°
target = 0                   # where we want the arm, in degrees
arm.go_to_position(0)        # hold it there

while True:
    # INPUT
    angle = enc.count / TICKS_PER_DEG

    # DECIDE
    new_target = target              # default: keep the same target
    if gp.just_pressed_a:
        new_target = 0               # A: down
    if gp.just_pressed_b:
        new_target = 45              # B: halfway
    if gp.just_pressed_y:
        new_target = 90              # Y: straight up

    # OUTPUT
    if new_target != target:         # only send a NEW target
        target = new_target
        arm.go_to_position(target * TICKS_PER_DEG, max_speed=60)
    robot.plot("target", target)
    robot.plot("angle", angle)

    robot.sleep(0.02)

Use max_speed to keep a heavy arm from slamming into place. Only call go_to_position() when the target changes. Each call restarts the PID, so calling it every loop with the same target throws away KI's progress.
