Redwing Quick Reference: Drive Systems

A drive object runs all your wheels together. It uses the encoders to measure how far the robot has gone and the IMU to measure which way it's facing, so you can say "go forward 0.5 m" or "rotate left 90°", and read back where the robot is.

Which way is which

Redwing uses the standard robotics convention: +X is forward, +Y is left, and counter-clockwise (left) rotation is positive. Every position, heading and signed command follows it.

Positive (+)Negative (−)
x, move_by(), vx, forwardforwardbackward
y, strafe_by(), vyleftright
heading, rotate_by(), omega, turnleft (counter-clockwise)right (clockwise)

x and y are meters from where the robot started. heading is degrees, 0 at start, and wraps 0–360 (a small rotation right reads 350).

Setup: differential (tank) drive

left_motor  = robot.D0.motor()
right_motor = robot.D1.motor()
left_motor.attach_encoder(robot.D2.encoder())
right_motor.attach_encoder(robot.D3.encoder())

drive = robot.differential_drive(
    left_motor=left_motor,   right_motor=right_motor,
    imu=robot.imu(),
    wheel_diameter_mm=96,
    track_width_mm=280,      # center of left wheel to center of right wheel
    ticks_per_rev=537.7,     # encoder ticks per WHEEL revolution
)

The drive uses each motor's attached encoder, so you don't pass the encoders again.

Two motors per side? Group them, then pass left=/right= instead of the motors:

left  = robot.motor_group(front_left, back_left,   encoder=left_enc)
right = robot.motor_group(front_right, back_right, encoder=right_enc)

drive = robot.differential_drive(left=left, right=right, imu=robot.imu(), ...)

Setup: mecanum drive

fl = robot.D0.motor();  fl.attach_encoder(robot.D4.encoder())    # front-left
fr = robot.D1.motor();  fr.attach_encoder(robot.D5.encoder())    # front-right
bl = robot.D2.motor();  bl.attach_encoder(robot.D6.encoder())    # back-left
br = robot.D3.motor();  br.attach_encoder(robot.D7.encoder())    # back-right

drive = robot.mecanum_drive(
    fl=fl, fr=fr, bl=bl, br=br,
    imu=robot.imu(),
    wheel_diameter_mm=96,
    track_width_mm=300,      # left wheels to right wheels
    wheelbase_mm=280,        # front wheels to back wheels
    ticks_per_rev=537.7,
)

This uses all eight D ports. Name each motor by where it is on the robot, not by how it's wired.

Check before the first run

  1. Every motor spins its wheel forward with positive power. If not, motor.invert().
  2. Every encoder count goes up when its wheel rolls forward. If not, motor.encoder.invert().
  3. ticks_per_rev is measured by hand (see the Encoders reference). A wrong value makes every distance wrong by the same factor.

If forward() never stops, or rotate_left() rotates right, one of these is wrong.

Moving (after robot.start())

drive.forward(0.5)              # 0.5 m forward, then stop  (power=50 default)
drive.backward(0.3, power=30)
drive.rotate_left(90)           # rotate in place by 90°      (power=40 default)
drive.rotate_right(45)
drive.rotate_to(180)            # rotate to FACE heading 180°, the shorter way
drive.rotate_to(0, direction="left")  # ...or force "left" / "right"

# same moves with a sign instead of a direction in the name
drive.move_by(-0.3)             # + forward, - backward
drive.rotate_by(-45)            # + left, - right

# mecanum only
drive.strafe_left(0.3)          # slide sideways, still facing forward
drive.strafe_right(0.3)
drive.strafe_by(-0.3)           # + left, - right
drive.strafe(0.4, 45)           # any direction, counter-clockwise from forward:
                                # 0=fwd, 90=left, 180=back, 270=right

These wait until the move is done, so your program pauses on that line. Use them for autonomous step-by-step routines, not inside a gamepad loop.

Prefer rotate_to() for routines. The robot keeps spinning a little after each rotation. rotate_left(90) four times adds those extra degrees up; rotate_to() aims at a fixed heading, so each rotation fixes the last one's error. Still rotating a few degrees too far? Aim a few degrees short.

Robot stalls just short of the target?

Moves slow down near the end. If a wheel stops turning before the robot gets there, set that motor's minimum power (setup, before robot.start()):

left_motor.set_min_power(25)     # lowest power that still turns this wheel
right_motor.set_min_power(18)

Default without it: 20% for straight moves, 15% for rotations. This only affects the drive's moves, not set_power() or drive.drive().

Driving continuously (gamepad, sensors)

drive.drive(forward=50, turn=0)        # differential: turn + = left, - = right
drive.move(vx=50, vy=0, omega=0)       # mecanum: vy + = left, omega + = left
drive.stop()

All values are % power, -100 to 100. These return right away and keep the motors running until you send something else or stop().

Driving by speed (smooth, fine control)

Power isn't speed: the same power goes slower on carpet or a low battery, and small powers may not move the robot at all. set_velocity() uses the encoders to hold a real speed instead.

drive.set_max_rpm(312)                 # setup: the RPM printed on the drive motors

drive.set_velocity(0.3, omega=45)       # differential: m/s forward, degrees/s left
drive.set_velocity(0.3, 0.1, 45)        # mecanum: vx, vy (m/s, + = left), omega

drive.max_speed                         # top speed, m/s (worked out for you)
drive.max_angular_speed                 # top rotation speed, degrees/s

Chain or gears between motor and wheel? Add the ratio, as motor turns per wheel turn: drive.set_max_rpm(435, gear_ratio=2).

Real robots are a bit slower than the printed RPM (it's measured with no load). That's fine for most driving. If the robot can't keep up near full stick, measure its real top speed instead: run drive.drive(100) for a second, read the encoder speed, and use drive.set_max_speed(m_per_s). If a wheel needs a push to start turning, motor.set_min_power() is used here too.

drive.set_velocity_mode("pico") runs the speed control on the Pico instead of in Python. It reacts faster and isn't slowed down by busy code; your code stays the same.

Where am I?

x, y, heading = drive.pose     # meters, meters, degrees
drive.x;  drive.y;  drive.heading

drive.reset_pose()             # call this spot (0, 0, 0°)

The pose updates on its own 50 times a second, and shows up live on the dashboard Map tab.

What the IMU does

  • Gives the drive its heading. Wheels slip when the robot rotates, so heading from encoders alone drifts fast. Always pass imu=robot.imu() if you have one.
  • Tells rotate_left(), rotate_right(), rotate_by() and rotate_to() when to cut power (within about 1.5°). The robot can coast a little past that.
  • Does not steer forward() straight. If the robot curves, check the motors and wheels.
  • BNO085/BNO055: heading doesn't drift. MPU-6050: drifts about 0.5–2° per minute.

Example: drive a square

from redwing import Robot

robot = Robot()
left_motor  = robot.D0.motor()
right_motor = robot.D1.motor()
left_motor.attach_encoder(robot.D2.encoder())
right_motor.attach_encoder(robot.D3.encoder())

drive = robot.differential_drive(
    left_motor=left_motor,   right_motor=right_motor,
    imu=robot.imu(),
    wheel_diameter_mm=96, track_width_mm=280, ticks_per_rev=537.7,
)
robot.start()

heading = 0
for side in range(4):
    drive.forward(0.5)
    heading = heading + 90
    drive.rotate_to(heading % 360)   # 90, 180, 270, 0

x, y, heading = drive.pose
robot.log("Ended at x:", x, " y:", y, " heading:", heading)

Example: mecanum with a gamepad

from redwing import Robot

robot = Robot()
fl = robot.D0.motor();  fl.attach_encoder(robot.D4.encoder())
fr = robot.D1.motor();  fr.attach_encoder(robot.D5.encoder())
bl = robot.D2.motor();  bl.attach_encoder(robot.D6.encoder())
br = robot.D3.motor();  br.attach_encoder(robot.D7.encoder())

drive = robot.mecanum_drive(
    fl=fl, fr=fr, bl=bl, br=br,
    imu=robot.imu(),
    wheel_diameter_mm=96, track_width_mm=300, wheelbase_mm=280, ticks_per_rev=537.7,
)
drive.set_max_rpm(312)             # RPM printed on the motors
gp = robot.gamepad
gp.set_axis_mode("ros")            # sticks use the robot frame: x = up, y = left
gp.set_deadband(0.1)               # ignore a stick that doesn't quite centre
robot.start()

while True:
    # INPUT
    forward = gp.left_x * drive.max_speed * 0.6       # left stick up    = forward
    slide   = gp.left_y * drive.max_speed * 0.6       # left stick left  = slide left
    spin    = gp.right_y * drive.max_angular_speed * 0.4   # right stick left = rotate left

    # DECIDE
    if gp.just_pressed_a:
        drive.reset_pose()         # A: call this spot (0, 0, 0°)

    # OUTPUT
    drive.set_velocity(forward, slide, spin)
    robot.log("x:", drive.x, " y:", drive.y, " heading:", drive.heading)

    robot.sleep(0.02)
