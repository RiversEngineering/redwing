How to use this file

Open practice_debug.py and work through the bugs in order. For the commented-out ones: uncomment the whole block, run python3 practice_debug.py, read the error Python shows you, then edit the code until it's fixed and the crash is gone. For the live ones: read the spec comment above the function carefully, compare it to what the code actually does, and fix the logic so the printed value matches the spec.

💡 Tip
If you ever see TypeError: some_function() missing 1 required positional argument: 'b', Python is telling you exactly what's wrong: the function's def line expects a value for parameter b, and the call site simply never supplied one. The fix is almost always at the call site, not inside the function itself — add the missing argument.

Bug 1 — missing return

def compute_area(width, height):
    print(width * height)

total_area = compute_area(5, 4) + 10
print(total_area)

compute_area is supposed to hand its answer back so it can be reused in more math, but it only print()s it, so it implicitly returns None. Error: TypeError (you can't add None and an int). Fix: change print(width * height) to return width * height. Expected output after the fix: 30

Bug 2 — forgot to call the function

def triple(n):
    return n * 3

result = triple  # missing the (4)
total = result + 5
print(total)

triple with no parentheses doesn't call the function at all — it grabs the function itself, the way you'd grab a value out of a variable. Error: TypeError because you can't add a number to a function object (don't worry about matching the exact wording Python prints for the function — it can look different from run to run; what matters is that math with it fails). Fix: change result = triple to result = triple(4). Expected output after the fix: 17

Bug 3 — arguments in the wrong order (no crash)

def subtract(a, b):
    return a - b

remaining_distance = subtract(5, 20)
print(remaining_distance)

Nothing crashes here — that's what makes this bug sneaky. A 20-mile race with 5 miles already driven should leave 15 miles remaining, but subtract(5, 20) computes 5 - 20, not 20 - 5. Current (wrong) output: -15. Fix: swap the argument order to subtract(20, 5). Expected output after the fix: 15

Bug 4 — dedented line runs at the wrong time

def summarize_lap(lap_time, best_time):
    difference = lap_time - best_time
print(f"You were {difference} seconds off the best time.")

summarize_lap(32, 30)

The print(...) line was meant to be the last line inside the function, but it isn't indented — so it isn't part of the function at all. Python runs it immediately, once, the moment it finishes reading the def block — long before summarize_lap is ever called, and before difference exists anywhere. Error: NameError: name 'difference' is not defined. Fix: indent the print(...) line so it's part of the function body. Expected output after the fix: You were 2 seconds off the best time.

Bug 5 — missing a required argument

def average_two(a, b):
    return (a + b) / 2

print(average_two(10))

average_two needs two arguments, but the call site only supplies one. Error: TypeError: average_two() missing 1 required positional argument: 'b'. Fix: supply the second argument, e.g. average_two(10, 20). Expected output after the fix: 15.0

Bug 6 — off-by-one boundary check (no crash)

def is_too_close(distance_cm):
    # Spec: a distance of 10 cm or less counts as "too close"
    if distance_cm < 10:
        return True
    return False

print(is_too_close(5))    # True
print(is_too_close(10))   # should be True
print(is_too_close(15))   # False

The spec's own comment says 10 itself should count as "too close," but distance_cm < 10 is False when distance_cm is exactly 10. Every other value already works correctly — only the exact boundary is wrong. Current (wrong) output for is_too_close(10): False. Fix: change < to <=. Expected output after the fix, in order: True, True, False

Bug 7 — accumulator reset inside the loop (no crash)

def sum_range(n):
    for i in range(1, n + 1):
        total = 0
        total = total + i
    return total

print(sum_range(5))

total = 0 sits inside the loop, so it wipes out the running total on every single pass instead of only once at the start. The function ends up returning just the last number added, not the true sum. Current (wrong) output: 5. Fix: move total = 0 to before the for loop. Expected output after the fix: 15
