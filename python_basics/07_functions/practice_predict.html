Assignment 7 Practice: Predict the Output

⏱ Estimated time: 25 minutes Prerequisite: Assignment 7 — Functions

Reading code and predicting what it will print — before you run it — is one of the fastest ways to find gaps in how you think about functions. Each snippet below is complete and correct Python. Your job is only to predict its output, not to fix anything.

What you'll practice
  • Tracing a function call to the value it returns
  • Telling return apart from print() when a function does both
  • Recognizing when a missing return gives back None
  • Confirming local variables never overwrite a global with the same name
  • Tracing a function that calls another function to build its result
  • Default parameter values used with no argument supplied
  • The order code actually runs in — definitions vs. calls

Prediction 1 — a simple return value

def double(n):
    return n * 2

print(double(6))

Output: 12

Prediction 2 — the same function, two different calls

def cube(n):
    return n * n * n

print(cube(2))
print(cube(3))

Output (in order): 8 then 27

Prediction 3 — a function with no return

def shout(word):
    print(word + "!!!")

print(shout("watch out"))

Two lines print. shout prints its own message as a side effect, then hands nothing back — so the outer print() shows whatever shout() returned. Output: watch out!!! then None

Prediction 4 — same variable name, inside and outside

score = 100

def reset_score():
    score = 0
    print(score)

reset_score()
print(score)

Output (in order): 0 then 100 — the score = 0 inside reset_score() is a brand-new local variable. The global score is never touched.

Prediction 5 — one function calling another

def double(n):
    return n * 2

def add_five(n):
    return n + 5

def double_then_add_five(n):
    doubled = double(n)
    return add_five(doubled)

print(double_then_add_five(10))

Output: 25 — 10 doubled is 20, then 20 plus 5 is 25.

Prediction 6 — a default parameter value

def greet(name="Robot"):
    return f"Hello, {name}!"

print(greet())

Output: Hello, Robot! — calling greet() with no argument at all falls back to the default value written in the def line.

Prediction 7 — order matters (calls, not definitions)

def first_message():
    print("A")

def second_message():
    print("B")

print("start")
first_message()
print("middle")
second_message()
print("end")

Both functions are defined at the top, but nothing inside them runs until they're actually called — and those calls happen further down, interleaved with plain print() statements. Predict the order all five lines print in, top to bottom. Output: start, A, middle, B, end

Prediction 8 — Bonus, we haven't taught this, take a guess!

def check_temperature(temp):
    if temp > 100:
        return "too hot"

result = check_temperature(50)
print(result)

The return only lives inside the if block. temp is 50, so temp > 100 is False and that return never runs. What happens when a function simply reaches the end of its body without ever hitting a return? Take your best guess before revealing. Output: None — falling off the end of a function with no return statement executed behaves exactly like a function that never had a return at all.
