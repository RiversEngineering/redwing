⏱ Estimated time: 50 minutes Prerequisite: Assignment 6 — For Loops & Lists

Take a look inside examples/ and you'll see lines like motor.set_power(60) and robot.sleep(2). Those are functions — someone else already wrote the logic inside them, and you just call them by name. This lesson teaches you to write your own functions, so you can package up your own reusable logic the same way.

What you'll learn
  • Why functions exist: naming a reusable chunk of logic instead of repeating it
  • How to define a function with def and call it to actually run it
  • The difference between parameters and arguments
  • How return sends a value back to the caller, unlike print()
  • Local scope: a variable made inside a function stays inside it

Why functions?

Imagine you need to greet three different people in your program. Without functions, you'd write the same print() logic over and over. A function lets you write that logic once, give it a name, and then reuse it as many times as you like. This isn't just about saving typing — it also makes your code read like a sentence of intent. Compare a page of raw math to a line that says clamp_power(150). The second one tells you exactly what's happening without you needing to read the details.

Defining and calling a function

You create a function with a def block. Nothing inside it runs yet — def just teaches Python the recipe. The code only runs when you call the function by writing its name followed by parentheses.

def greet(name):
    print(f"Hello, {name}!")

greet("Ada")
greet("Grace")

Output:

Hello, Ada!
Hello, Grace!

Notice the def greet(name): line itself printed nothing — it just defined the function. Each call below it is what actually ran the code, once per call.

Parameters vs. arguments

These two words get mixed up constantly, so it's worth being precise:

  • A parameter is the placeholder name in the def line — like name in def greet(name):.
  • An argument is the actual value you pass in when you call the function — like "Ada" in greet("Ada").

In short: parameters are the blanks in the recipe, arguments are what you actually put in them.

return vs. print

print() only displays something on the screen — it doesn't give anything back to the rest of your code. return is different: it sends a value back to whoever called the function, so you can store it in a variable or use it in more math.

def square(n):
    return n * n

result = square(5)
print(result + 1)   # 26 -> we can do more math with the returned value

If a function never hits a return statement, calling it gives back a special value called None — Python's way of saying "nothing here."

💡 Tip
A good way to tell the two apart: print() is for showing a human something on screen. return is for handing a value back to your own code so it can keep working with it. A function can do both, or either, or neither — but if you need to use the result later, you need return.

Local scope: variables stay inside their function

A variable created inside a function only exists inside that function — it's called a local variable. It doesn't leak out into the rest of your program, even if a variable with the same name exists outside.

power = 10

def use_local_power():
    power = 999   # this is a brand-new, separate variable
    print(power)

use_local_power()   # prints 999
print(power)         # prints 10 -- the outer power was never touched
⚠️ Common mistake
Using print() instead of return inside a function that's supposed to hand back a value. The function will happily display the right number on screen, but any code that tries to use its result — like result = my_function(5) — ends up with result = None, since the function never actually returned anything. Trying to do math with None (like None + 1) crashes with a TypeError. You'll fix exactly this bug in Task 4.
