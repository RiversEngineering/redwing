What is a program?

A program is just a list of instructions that the computer follows, exactly as written, one line at a time, from top to bottom. Think of it like a recipe: the computer doesn't skip ahead, doesn't guess what you meant, and doesn't do anything you didn't tell it to do. If you write three instructions, the computer runs the first one completely, then the second, then the third. That's it — that's the whole idea behind every piece of software, including the code that will one day drive your robot.

Your first command: print()

The simplest thing a program can do is display text on the screen. In Python, we do that with print(). Whatever you put inside the parentheses gets shown on the screen when the program runs.

print("Hello, robotics team!")

Notice the quotation marks. In Python, text like this is called a string — a "string" of characters. The quotes mark exactly where the string starts and where it ends. Everything between the opening " and the closing " gets printed exactly as you typed it. If you run the line above, the computer will print:

Hello, robotics team!
💡 Tip
You can use either double quotes "like this" or single quotes 'like this' — just make sure the opening and closing quote match.

Comments: notes for humans

Sometimes you want to leave a note in your code that explains what's going on — but you don't want the computer to try to run it as an instruction. That's what a comment is. Any line that starts with a # (called a "hash" or "pound sign") is completely ignored when the program runs. It's there purely for you and other people reading your code.

# This line does nothing when the program runs
print("But this line does!")

Programmers use comments constantly — to explain tricky bits of code, to leave reminders, or to temporarily disable a line without deleting it (this is called "commenting out" a line, and you'll do exactly that in Task 5 below).

Running a script on the Pi

A Python program saved in a file is often called a script. To run your script on the Raspberry Pi, open a terminal, navigate to the folder containing your file, and type:

python3 starter.py

This tells the computer: "use the Python 3 program to run the instructions in the file called starter.py." You should get in the habit of running your script after every single change you make — that's the fastest way to know whether your edit worked.

Order matters

Remember: Python runs your lines top to bottom, in the exact order they're written. If you print "Robot ready!" before you print "Powering on...", the screen will show "Robot ready!" first — even though that doesn't make logical sense. The computer doesn't understand meaning, only order. Swapping two lines is one of the most common fixes you'll make as you write code.

Reading an error message

Eventually, you'll make a typo, and Python will refuse to run your program. This is completely normal — it happens to every programmer, every day, forever. Python's job in that moment is to tell you what went wrong and roughly where. For example, if you forget the closing quote on a string:

print("Almost done!)

Python will stop and show something like:

  File "starter.py", line 27
    print("Almost done!)
                        ^
SyntaxError: unterminated string literal (detected at line 27)

Read this from the bottom up: SyntaxError means "you broke a grammar rule of the Python language." The words after it, unterminated string literal, mean "you opened a string with a quote but never closed it." And line 27 tells you exactly which line to look at. Errors aren't a sign you've failed — they're Python pointing directly at the fix.

⚠️ Common mistake
Forgetting to close a quote is one of the most common beginner errors. Every string needs a matching pair of quotes — one to open it, one to close it. If your program suddenly refuses to run after you added a print() line, check your quotes first.
