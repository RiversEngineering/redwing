The while Loop

A while loop repeats an indented block of code over and over, as long as its condition evaluates to True. Python checks the condition, and only if it's True does it run the block — then it goes back and checks the condition again. This re-checking happens every single pass, not just once at the start.

count = 5
while count > 0:
    print(count)
    count -= 1
print("Liftoff!")

Walk through it: count is 5, so count > 0 is True — the block runs, printing 5 and lowering count to 4. Python loops back to the while line and checks again: 4 > 0 is still True, so it runs again. This continues until count becomes 0 — now 0 > 0 is False, so Python skips the block entirely and moves on to print("Liftoff!"). Output: 5 4 3 2 1 Liftoff!, one per line.

Just like if, the block belongs to the loop because it's indented underneath the while line. The indentation rules you already know from Assignment 4 apply here too.

The Infinite Loop Trap

A while loop only stops when its condition becomes False. That means something inside the loop must change so the condition eventually flips. If nothing changes, the condition stays True forever, and you get an infinite loop — a program that never finishes.

# DANGER: this never stops! n is always 1, so n <= 5 is always True
n = 1
while n <= 5:
    print(n)

If you ever accidentally run something like this in a terminal, don't panic — press Ctrl+C to force-stop it. That's the emergency brake for a runaway program.

⚠️ Common mistake
Forgetting to update the variable the condition depends on — like leaving out n += 1 — is the single most common way to write an infinite loop by accident. Whenever you write a while loop, ask yourself: "what line makes this condition eventually False?"

The Counter Pattern

A counter is a variable that steps up (or down) by a fixed amount each pass through the loop — that's exactly what count -= 1 did above. You'll use this pattern constantly: "do this N times."

i = 1
while i <= 3:
    print(f"pass number {i}")
    i += 1

The Accumulator Pattern

An accumulator is a variable that builds up a running total across passes through the loop. You start it at 0 (or 1 for multiplying), and each pass you add (or multiply) something into it.

n = 1
total = 0
while n <= 5:
    total = total + n
    n += 1
print(f"Total: {total}")   # Total: 15
💡 Tip
Notice this loop uses two variables that change: n is the counter that controls when the loop stops, and total is the accumulator that stores the answer you actually care about. Loops often combine both patterns at once.

break — Leaving a Loop Early

Sometimes you want to exit a loop the instant something happens, even if the while condition is still True. That's what break does — it immediately jumps out of the loop, skipping the rest of the block and any remaining passes.

fuel = 100
while fuel > 0:
    fuel -= 12
    print(fuel)
    if fuel <= 20:
        break   # stop early — don't wait for fuel > 0 to become False

The Robot Connection: while True:

Here's the big idea this whole lesson is building toward. A robot's brain doesn't run once and quit — it runs forever, constantly re-checking its sensors. Python lets you write that directly: while True: is a condition that is always True, so the loop runs forever by design. The real "should I stop / should I turn / should I back up" logic doesn't live in the while condition at all — it lives in if statements (and sometimes break) written inside the loop. Here's a real excerpt from examples/05_obstacle_avoidance.py in this repo:

while True:
    d = sensor.distance

    if d > 0 and d < 25:
        # Obstacle — back up then turn right
        ...
    else:
        # Path clear — drive forward
        ...

The while True: never becomes False on its own — the robot keeps looping, reading its sensor, and deciding what to do, pass after pass, exactly like the loops you just practiced. You now have every ingredient you need to read that code: a loop, a condition check inside it, and a decision made from that check.
