Assignment 5 Practice: Predict the Output

⏱ Estimated time: 25 minutes Prerequisite: Assignment 5 — While Loops

Reading a while loop and predicting exactly what it will print — before you run it — is the single best way to build a real mental model of how loops work. Below are 8 short snippets pulled straight from the concepts in Assignment 5. For each one, write down your prediction first, then open practice_predict.py and run it with python3 practice_predict.py to see if you were right.

What you'll practice
  • Tracing a while loop's condition check before every pass, including the first
  • Recognizing when a loop's condition is already False, so the body never runs at all
  • The counter pattern and the accumulator pattern
  • break inside a while True: loop
  • Boundary conditions: < vs <=
  • A flag variable that turns a loop off from the inside (bonus — not yet taught)

Prediction 1 — basic countdown

n = 4
while n >= 0:
    print(n)
    n -= 1

Prediction: 4, 3, 2, 1, 0 — each on its own line

Prediction 2 — a condition that starts out False

n = 0
while n > 0:
    print(n)
    n -= 1
print("loop finished")

Prediction: nothing prints from the loop — only "loop finished"

This is the important edge case: Python checks n > 0 before it ever runs the block. Since n is already 0, the condition is False on the very first check, so the body runs zero times — it isn't skipped after one try, it never starts.

Prediction 3 — accumulator

n = 1
total = 0
while n <= 5:
    total += n
    n += 1
print(total)

Prediction: 15

Prediction 4 — break inside while True:

count = 0
while True:
    count += 1
    print(count)
    if count == 3:
        break

Prediction: 1, 2, 3 — each on its own line, then the loop stops

Prediction 5 — stepping by 2

n = 1
while n <= 10:
    print(n)
    n += 2

Prediction: 1, 3, 5, 7, 9

Prediction 6 — boundary comparison: <= vs <

Two separate loops, same starting value, two different operators.

print("Loop A:")
count = 1
while count <= 3:
    print(count)
    count += 1

print("Loop B:")
count = 1
while count < 3:
    print(count)
    count += 1

Loop A last value printed: 3

Loop B last value printed: 2

A one-character difference in the comparison — <= versus < — changes how many times the loop runs. This is exactly how off-by-one bugs sneak into real code.

Prediction 7 — break checked partway through

level = 50
step = 0
while level > 0:
    step += 1
    level -= 15
    if level < 10:
        break
print(f"stopped after step {step}, level = {level}")

Prediction: stopped after step 3, level = 5

Trace it: step 1 takes level to 35 (not < 10, keep going), step 2 takes it to 20 (still not < 10), step 3 takes it to 5 — and 5 is < 10, so break fires right there.

Prediction 8 (Bonus — we haven't taught this, take a guess!)

still_running = True
passes = 0
while still_running:
    passes += 1
    print(f"pass {passes}")
    if passes == 2:
        still_running = False
print("stopped")

Prediction: pass 1, pass 2, stopped — the loop body runs exactly twice

still_running is a flag variable — a variable whose only job is to be True or False. Instead of comparing a number, while still_running: just checks the flag directly, and code inside the loop flips it once it's time to stop. You'll see this pattern again and again once you start writing longer programs.

Check Yourself

1. In Prediction 2, why does the loop print nothing at all instead of printing once and then stopping? What does that tell you about when a while condition gets checked?

2. In Prediction 8, could you rewrite the loop to use a plain comparison (like while passes < 2:) instead of a flag variable and get the same result? Why might a flag variable still be useful even when a plain comparison would also work?

Quick Reference

PatternWhat to notice
Condition already FalseThe block runs zero times — it's checked before the first pass, not just after
CounterA variable stepped up/down by a fixed amount each pass (n += 1, n += 2, ...)
AccumulatorA variable that builds a running total (total += n)
<= vs <Changes exactly how many times the loop runs — check boundaries carefully
breakExits immediately, even mid-pass, even if the while condition is still True
Flag variableA True/False variable the loop condition checks directly; code inside flips it to stop
