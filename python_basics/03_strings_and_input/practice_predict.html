Assignment 3 Practice: Predict the Output

⏱ Estimated time: 25 minutes Prerequisite: Assignment 3 — Strings & Input

Reading code and predicting what it does before you run it is one of the fastest ways to actually learn a language — instead of just watching output scroll by, you're testing your own mental model of Python against reality. Below are 8 short snippets from practice_predict.py. For each one, write down your guess first, then check yourself.

What you'll practice
  • Reading f-strings and predicting what they print
  • Tracing string concatenation with +
  • Counting characters with len()
  • Spotting the difference between adding numbers and joining strings
  • Reasoning about an error without running the code

Predictions

Prediction 1 — a basic f-string.

name = "Ada"
print(f"Hi, {name}!")

Prediction: Hi, Ada!

Prediction 2 — joining two words with +.

first_word = "Robot"
second_word = "Builder"
print(first_word + " " + second_word)

Prediction: Robot Builder

Prediction 3 — len() on a string with a space in it.

print(len("Redwing Robotics"))

Prediction: 16 (the space between the two words counts as a character too)

Prediction 4 — an expression inside an f-string.

a = 6
b = 7
print(f"{a} times {b} is {a * b}")

Prediction: 6 times 7 is 42

Prediction 5 — convert, then do math.

age_text = "16"
age = int(age_text)
print(age + 4)

Prediction: 20

Prediction 6 — predict the error, don't run it. This snippet stays commented out in practice_predict.py — it is never executed. Instead of predicting printed text, predict what kind of error Python would raise if this line did run:

# print("Power level: " + 100)

Prediction (error type): TypeError — can only concatenate str (not "int") to str

Prediction 7 — a silent gotcha (no crash, but is it what you expect?).

qty = "5"
more = "3"
print(qty + more)

Prediction: 53 — the text "53", NOT the number 8. qty and more are both strings, so + joins them instead of adding them.

💡 Tip
This is exactly why the answer isn't 8 — Python doesn't look at what a string looks like, only what type it actually is. Two strings that happen to contain digits still get joined with +, never added.

Prediction 8 — bonus, we haven't taught this, take a guess!

print("-" * 10)

Prediction: ---------- (ten dashes — * repeats a string that many times)

Check Yourself

  • Predictions 2 and 7 both use + between two strings. Why does one clearly "join two words" while the other looks like it should be doing math but isn't?
  • Prediction 6 never actually runs. Why is it still useful to predict the error type for code you never execute?

Quick Reference

SyntaxWhat it does
f"{x}"Inserts the value of x (or any expression) directly into text.
"a" + "b"Joins two strings end to end. Both sides must already be strings.
len(text)Number of characters in the string text, including spaces.
int(text)Converts a numeric-looking string into a real number you can do math with.
"str" + intRaises a TypeError — Python won't silently guess what you meant.
"5" + "3"No error — but gives you the text "53", not the number 8.
