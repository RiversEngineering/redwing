Assignment 6 Practice: Debug It

⏱ Estimated time: 30 minutes Prerequisite: Assignment 6 — For Loops & Lists

Every one of the seven bugs below is a mistake real beginners make with lists and for loops. Some of them crash the program outright — those are written as comments in practice_debug.py so the file still runs. The rest are sneakier: they run just fine, no error message at all, but they print the wrong thing. Those are arguably the more important bugs to learn to spot, because your robot code won't always tell you when it's wrong — it'll just quietly do the wrong thing.

What you'll practice
  • Recognizing IndexError, AttributeError, and NameError before Python even shows them to you
  • Spotting a loop variable that got typo'd for the wrong variable
  • Catching off-by-one mistakes in range() bounds
  • Noticing when a filter condition points the wrong direction
  • Reading indentation carefully enough to tell what's really inside a loop

Bug 1 — reaching one index too far

# waypoints = [10, 25, 40, 55]
# print(waypoints[len(waypoints)])

Goal: print the last waypoint, 55.
Error: IndexError: list index out of range. len(waypoints) is 4, but the valid indices on a 4-item list are only 0, 1, 2, 3.
Corrected output: 55, using waypoints[-1].

Bug 2 — printing the wrong variable

readings = [12, 18, 25, 9]
last_value = 0
for reading in readings:
    print(last_value)

Goal: print each reading in the list, one per line.
Wrong behavior: no crash — it just prints 0 four times. The loop variable is reading, but the print statement references last_value, an unrelated variable that never changes.
Corrected output: 12, 18, 25, 9 (one per line).

Bug 3 — append() returns None

# squares = []
# squares = squares.append(1)
# squares = squares.append(4)
# squares = squares.append(9)
# print(squares)

Goal: build the list [1, 4, 9].
Error: AttributeError: 'NoneType' object has no attribute 'append'. .append() already modifies the list in place — it returns None, so re-assigning squares = squares.append(1) turns squares into None. The next line then tries to call .append() on None.
Corrected output: [1, 4, 9], by calling squares.append(1) on its own line, with no assignment.

Bug 4 — off-by-one in range()

for lap in range(1, 5):
    print(f"Lap {lap}")

Goal: print Lap 1 through Lap 5 — five laps.
Wrong behavior: no crash — range(1, 5) stops before 5, so it only prints laps 1 through 4 — one lap short.
Corrected output: Lap 1 through Lap 5, using range(1, 6).

Bug 5 — accumulator never initialized

# for n in [1, 2, 3]:
#     doubled.append(n * 2)
# print(doubled)

Goal: build the list [2, 4, 6].
Error: NameError: name 'doubled' is not defined. There's no doubled = [] line before the loop, so Python has no variable called doubled to append onto.
Corrected output: [2, 4, 6], by adding doubled = [] before the loop.

Bug 6 — filter condition points the wrong way

sensor_readings = [22, 19, 31, 8, 40]
for r in sensor_readings:
    if r > 20:
        print(r)

Goal: print only the readings below 20 (the low readings).
Wrong behavior: no crash — r > 20 prints the exact opposite set: the high readings (22, 31, 40) instead of the low ones.
Corrected output: 19, 8, using r < 20.

Bug 7 — a print() that isn't really inside the loop

countdown = [3, 2, 1]
for number in countdown:
    message = f"T-minus {number}"
print(message)

Goal: print a "T-minus" message for every number, one line per number.
Wrong behavior: this one is the sneakiest of all — it's perfectly valid Python, so there's no error message whatsoever. Look closely at the indentation: print(message) is not indented under the for, so it isn't part of the loop body — it runs exactly once, after the loop has already finished, using whatever message happened to be set to last. This is why careful indentation reading matters just as much as reading the code itself — Python won't warn you when a line quietly falls outside a loop.
Corrected output: T-minus 3, T-minus 2, T-minus 1, by indenting print(message) to match the line above it.

⚠️ Common mistake
IndexError almost always means an off-by-one somewhere: using len(a_list) instead of len(a_list) - 1, or forgetting that a range() stop value is excluded. When you see it, check your bounds before anything else.

Quick Reference

TypeWhat it means
IndexErrorCrash — tried to access an index that doesn't exist in the list
AttributeErrorCrash — called a method (like .append()) on something that doesn't have it, often None
NameErrorCrash — used a variable before it was ever created
Wrong comparison directionSilent — no crash, but an if filter using > instead of < (or vice versa) prints the opposite of what you wanted
Dedented codeSilent — no crash, but a line indented one level too little runs outside the loop instead of once per item
