Assignment 8 Practice: Predict the Output

⏱ Estimated time: 25 minutes Prerequisite: Assignment 8 — Objects & Methods

Reading code and predicting what it does before you run it is one of the fastest ways to actually learn a language — instead of just watching output scroll by, you're testing your own mental model of objects and methods against reality. Below are 9 short snippets from practice_predict.py. For each one, write down your guess first, then check yourself.

What you'll practice
  • Predicting string methods that return a new string: .upper(), .lower(), .strip()
  • Spotting the .append() / .sort() "returns None" trap before it bites you
  • Telling attributes (.real, .imag) apart from methods (.conjugate())
  • Tracing a chain of two methods called back to back
  • Reasoning about a TypeError without running the code

Predictions

Prediction 1 — .upper() and .lower() on a string.

callsign = "scout-7"
print(callsign.upper())
print(callsign.lower())

Prediction: SCOUT-7 then scout-7

Prediction 2 — .strip() and len() before and after.

label = "   drone-unit   "
print(len(label))
print(len(label.strip()))

Prediction: 16 then 10 (3 leading spaces + "drone-unit" (10 characters) + 3 trailing spaces = 16; strip removes only the 6 outer spaces, leaving the 10-character word)

Prediction 3 — the .append() trap, printed directly.

readings = [12, 18, 9]
print(readings.append(25))

Prediction: None — NOT [12, 18, 9, 25]. .append() does add 25 to readings in place, but the value it hands back — the thing print() actually displays — is always None.

Prediction 4 — .sort() on its own line, list printed afterward.

crew = ["Priya", "Sam", "Amir"]
crew.sort()
print(crew)

Prediction: ['Amir', 'Priya', 'Sam'] — alphabetical order. Because .sort() is called on its own line here (not printed directly), we get to see the real, mutated list. If you had written print(crew.sort()) instead, you'd see None — same trap as Prediction 3.

Prediction 5 — complex number attributes.

z = 5 + 12j
print(z.real)
print(z.imag)

Prediction: 5.0 then 12.0 — no parentheses needed, these are attributes: plain data already sitting on the object.

Prediction 6 — the matching method.

print(z.conjugate())

Prediction: (5-12j) — this one needs parentheses because it's a method: it computes and returns a brand-new complex number with the imaginary part flipped.

Prediction 7 — method chaining.

print("  Hi  ".strip().upper())

Prediction: HI — .strip() runs first and returns "Hi", then .upper() runs on that result, turning it into "HI".

💡 Tip
Read a chain of methods left to right: each one runs on whatever the one before it just returned. " Hi ".strip().upper() is really two steps happening in a row — first strip, then upper on the stripped result — just written on one line.

Prediction 8 (Bonus — we haven't taught this, take a guess!).

print("redwing".count("i"))

Prediction: 1 — .count() is a string method that counts how many times something appears. "redwing" has exactly one "i".

Prediction 9 — predict the error, don't run it. These lines stay commented out in practice_predict.py — they are never executed. Instead of predicting printed text, predict what kind of error Python would raise if this ran:

# z2 = 5 + 12j
# print(z2.real())

Prediction (error type): TypeError: 'float' object is not callable — z2.real is an attribute (just a float value, like 12.0), not a method. Adding () after it tries to CALL that float like a function — and floats aren't callable.

Check Yourself

  • Predictions 3 and 4 both involve None. Why does Prediction 4 print the real sorted list while Prediction 3 prints None, even though both methods mutate their list the same way?
  • Prediction 9 never actually runs. How do z2.real (Prediction 5) and z2.real() (Prediction 9) differ, and why does only one of them need parentheses to work?

Quick Reference

SyntaxWhat it does
s.upper() / s.lower()Returns a NEW string, uppercase/lowercase — s itself is unchanged.
s.strip()Returns a NEW string with leading/trailing whitespace removed.
lst.append(x)Adds x to lst in place — returns None.
lst.sort()Sorts lst in place — also returns None.
c.real / c.imagAttributes — the real/imaginary parts of a complex number. No parentheses.
c.conjugate()Method — returns a new complex number with the imaginary part flipped.
s.count(sub)Counts how many times sub appears in s.
a.b().c()Chaining — .c() runs on whatever .b() returned, left to right.
