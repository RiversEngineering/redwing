Assignment 8 Practice: Debug It

⏱ Estimated time: 30 minutes Prerequisite: Assignment 8 — Objects & Methods

practice_debug.py contains seven bugs, all involving objects and methods. Some would crash the program outright, so those are left commented out — read them and reason out the error before you ever run anything. Others are sneakier: the code runs without crashing, but prints something odd or just plain wrong, so those are left live for you to run and observe.

What you'll practice
  • Recognizing the .append() "returns None" trap when its result is captured into a variable
  • Spotting a method called without its () — it doesn't crash, it just never runs
  • Reading a TypeError from treating an attribute like a method
  • Reading an AttributeError from a typo or a method used on the wrong type
  • Reading a TypeError from sorting a list of mixed, uncomparable types

Bugs

Bug 1 — capturing .append()'s return value. Live — does not crash.

inventory = ["battery", "chassis"]
updated = inventory.append("wheel")
print(updated)

Intended: add "wheel" to inventory and print the updated list: ['battery', 'chassis', 'wheel']. What actually prints: None. .append() did add the wheel — inventory itself is correct — but it returns None, so updated was never going to hold the list. Fix: call .append() on its own line, then print inventory directly.

Bug 2 — method called without (). Live — does not crash.

robot_name = "titan"
print(robot_name.upper)

Intended: print TITAN. What actually happens: no () means .upper is never called — instead of the transformed text, it prints something like <built-in method upper of str object at ...>, a description of the method itself rather than its result. (The exact address after "at" will differ every time you run it — don't worry about matching it, just recognize the shape of the output.) Fix: add the parentheses: robot_name.upper().

Bug 3 — calling an attribute like a method. Commented out — would crash.

# c = 2 + 9j
# print(c.real())

Intended: print the real part of c: 2.0. Error type: TypeError: 'float' object is not callable. c.real is an attribute — already just a plain number — and putting () after it tries to call that number as if it were a function. Fix: drop the parentheses: c.real.

Bug 4 — typo'd method name. Commented out — would crash.

# word = "robot"
# print(word.uppr())

Intended: print ROBOT. Error type: AttributeError: 'str' object has no attribute 'uppr'. .uppr() simply doesn't exist — it's a typo for .upper(). Fix: correct the spelling.

Bug 5 — a list method used on a string. Commented out — would crash.

# message = "hello"
# message.append("!")

Intended: add an exclamation point onto the end of the message. Error type: AttributeError: 'str' object has no attribute 'append'. .append() is a list method — strings don't have it, because strings are immutable (nothing about a string can be changed in place). Fix: build a new string instead: message = message + "!", giving hello!.

Bug 6 — sorting mixed types. Commented out — would crash.

# mixed = [3, "two", 1]
# mixed.sort()

Intended: sort a list of priority numbers into [1, 2, 3]. Error type: TypeError: '<' not supported between instances of 'str' and 'int'. The word "two" snuck in as text instead of the number 2 — .sort() has no rule for comparing a string to an int, so it gives up. Fix: make every item the same type — change "two" to 2.

Bug 7 — missing () inside an f-string. Live — does not crash.

pilot = "maria"
print(f"Pilot: {pilot.upper}")

Intended: print Pilot: MARIA. What actually happens: same root problem as Bug 2, just tucked inside an f-string — {pilot.upper} has no parentheses, so instead of the uppercase name, the sentence embeds a description of the method itself, something like Pilot: <built-in method upper of str object at ...>. Fix: add the parentheses inside the braces: {pilot.upper()}.

⚠️ Common mistake
Seeing AttributeError almost always means one of two things: either you typo'd the method's name (Bug 4), or you're calling a method that the object's type simply doesn't have — often because you meant to call it on a different type, like a list method on a string or vice versa (Bug 5). Read the error message itself: it names both the type and the missing attribute, e.g. 'str' object has no attribute 'append' tells you exactly what went wrong.

Check Yourself

  • Bugs 2 and 7 both "fail silently" — no crash, just wrong output. What's the one thing missing from both, and why doesn't Python complain about it?
  • Bugs 3, 4, and 5 all crash, but with different messages. Which one is about calling something that isn't callable, and which two are about a method that doesn't exist at all?
