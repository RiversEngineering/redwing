What Is an Object?

An object is a value that bundles together data (called attributes) and the actions it can perform (called methods). You've been using objects since Lesson 1 without calling them that — every string, every list, every number is an object.

Python objects use dot notation to expose their attributes and methods:

  • thing.attribute — reads a piece of data off the object. No parentheses. It's just a value sitting there.
  • thing.method(args) — calls an action the object can perform. Always has parentheses, even if there are no arguments: ().

The parentheses are the tell: seeing them means "this is happening right now," while their absence means "this is just data."

String Methods

Strings have methods that transform them. Each one returns a brand-new string — the original string is never changed.

team_name = "Redwing Robotics"
print(team_name.upper())   # REDWING ROBOTICS
print(team_name.lower())   # redwing robotics
print(team_name)           # Redwing Robotics  <- unchanged!

Notice len(team_name) looks similar but is not a method call — it's a plain function that takes the string as an argument. There's no dot. Both give you information about the string, but only .upper() and .lower() are methods living on the string object itself.

.strip() removes whitespace from both ends of a string, again returning a new string:

raw = "   scout-bot   "
print(len(raw))          # 15  (spaces included)
print(len(raw.strip()))  # 9   (spaces gone)
print(raw)                # "   scout-bot   " <- unchanged!
💡 Tip
If you want to keep the stripped version, you have to save it: clean = raw.strip(). The method never changes raw itself — strings can't be changed in place at all, a property called being "immutable."

List Methods — and a Trap

Lists work differently. .append(x) and .sort() change the list in place (this is called mutating it) and both hand back None — not the updated list.

fleet = ["scout", "hauler", "sentry"]
fleet.append("drone")
fleet.sort()
print(fleet)   # ['drone', 'hauler', 'scout', 'sentry']
⚠️ Common mistake
A very common trap: x = my_list.append(5) does NOT make x the new list — it makes x equal to None, because .append() returns None. The list was still updated — my_list itself has the new item — you just captured the wrong thing. The fix is to call the method on its own line, then print the original list variable.

Attribute vs. Method: Complex Numbers

Python has a built-in complex number type, useful here because it makes the attribute/method distinction crystal clear with no custom classes involved:

c = 3 + 4j
print(c.real)          # 3.0   <- attribute: just data, no parens
print(c.imag)          # 4.0   <- attribute: just data, no parens
print(c.conjugate())   # (3-4j) <- method: computes and returns something new

c.real and c.imag are attributes — the real and imaginary parts are just numbers sitting on the object, nothing to compute. c.conjugate() is a method — it performs a calculation (flips the sign of the imaginary part) and returns a brand-new complex number, so it needs parentheses.

Reading Real Robot Code

Here is the complete, unmodified contents of examples/01_drive.py from this repository:

"""Example 1 — Drive a single motor.

The simplest possible program. One motor runs at half power for two
seconds, then stops.

Hardware
--------
- Motor controller wired to port D0 (dual-pin, sign-magnitude mode)
"""

from redwing import Robot

robot = Robot()

motor = robot.D0.motor()   # configure D0 as a sign-magnitude motor

robot.start()              # lock in configuration and enable commands

motor.set_power(50)        # 50 % forward (-100 to +100)
robot.sleep(2)
motor.stop()

Guided annotation: Line 13, robot = Robot(), creates a new Robot object — the parentheses after Robot are what actually build it. Line 15, motor = robot.D0.motor(), first reads robot.D0 as an attribute (port D0, no parens), then calls .motor() as a method that builds and returns a new motor object. Lines 17, 19, 20, and 21 — robot.start(), motor.set_power(50), robot.sleep(2), and motor.stop() — are all method calls, each one an action performed by an object that already exists.

And here is the complete, unmodified contents of examples/05_obstacle_avoidance.py:

"""Example 5 — Obstacle avoidance.

Drives forward until something is closer than 25 cm, then backs up,
turns, and tries again.

Hardware
--------
- Left motor controller  → D0
- Right motor controller → D1
- HC-SR04 ultrasonic     → D2
"""

from redwing import Robot

robot = Robot()

left   = robot.D0.motor()
right  = robot.D1.motor()
sensor = robot.D2.ultrasonic()

robot.start()

while True:
    d = sensor.distance

    if d > 0 and d < 25:
        # Obstacle — back up then turn right
        left.set_power(-50)
        right.set_power(-50)
        robot.sleep(0.5)

        left.set_power(60)
        right.set_power(-60)
        robot.sleep(0.4)
    else:
        # Path clear — drive forward
        left.set_power(60)
        right.set_power(60)

    robot.sleep(0.05)

Guided annotation: Lines 17–19 create three objects at once — left and right from .motor() calls on the robot.D0 and robot.D1 attributes, and sensor from a .ultrasonic() call on robot.D2. The key line is 24, d = sensor.distance — no parentheses, because reading the current distance is just data, an attribute, not an action. Everywhere else you see left.set_power(...), right.set_power(...), and robot.sleep(...), those are method calls — actions being performed, each with parentheses.
