Assignment 4 Practice: Debug It

⏱ Estimated time: 30 minutes Prerequisite: Assignment 4 — Making Decisions with Conditionals

Not every bug crashes your program. Some bugs are loud — Python refuses to run at all and shows you an error message. Others are quiet — the code runs just fine and prints something, it's just wrong, and nothing tells you that. Both kinds show up in practice_debug.py in this folder. Your job is to find and fix all 7.

What you'll practice
  • Recognizing SyntaxError, IndentationError, and TypeError by what triggers them
  • Catching a wrong and/or that never fires the branch it should
  • Catching elif branches made unreachable ("dead code") by their own ordering
  • Catching off-by-one boundary bugs (< where <= was meant)

The crash-bugs (1, 2, 3, and 7 below) are shipped fully commented out in practice_debug.py — that's the only reason the file runs at all as distributed. The logic-only bugs (4, 5, and 6) are live: the file runs, but prints the wrong thing for each of them.

Bug 1 — assignment instead of comparison

# Goal: print "Threshold reached" when x is exactly 10.
x = 10
if x = 10:
    print("Threshold reached")

Error type: SyntaxError. = assigns; == compares. An if needs a comparison, so Python refuses to run this at all.

Fix: change if x = 10: to if x == 10:. Corrected output: Threshold reached

Bug 2 — missing colon

# Goal: print "Motor cool" when motor_temp_c is 40 or below.
motor_temp_c = 35
if motor_temp_c <= 40
    print("Motor cool")

Error type: SyntaxError. Python uses the colon at the end of an if/elif/else line to know an indented block is coming. Without it, the line is invalid.

Fix: add the colon: if motor_temp_c <= 40:. Corrected output: Motor cool

Bug 3 — inconsistent indentation

# Goal: print "Sensor error" if reading is negative, otherwise print
# the reading itself.
reading = -5
if reading < 0:
    print("Sensor error")
else:
print(reading)

Error type: IndentationError. The if body is indented 4 spaces, but the else body isn't indented at all — Python expects an indented block right after a colon and doesn't find one.

Fix: indent the line under else: to match the if body's 4 spaces. Corrected output (with reading = -5): Sensor error

💡 Tip
Every line inside the same block must be indented by the exact same amount. Python doesn't care whether you use 2 spaces or 4, as long as you're consistent within a block and your editor isn't secretly mixing tabs and spaces. If you ever see IndentationError: expected an indented block, look at the line right after your colon first.

Bug 4 — wrong logical operator

# Goal: sound the alarm if the temperature is too low (under 32) OR
# too high (over 100).
temperature = 105
if temperature < 32 and temperature > 100:
    print("ALARM: temperature out of safe range")
else:
    print("Temperature normal")

What's wrong: this one doesn't crash — it just always gives the wrong answer. No number can be both under 32 and over 100 at the same time, so and makes the whole condition False no matter what — the alarm can never sound. The goal says "OR," so the code should say or.

As shipped, this prints: Temperature normal (wrong — 105 should trigger the alarm)

Fix: change and to or. Corrected output: ALARM: temperature out of safe range

Bug 5 — elif ordering hides a branch

# Goal: give a discount tier based on order_total:
#   under $10  -> "Tiny order discount"
#   under $100 -> "Standard discount"
#   otherwise  -> "No discount"
order_total = 5
if order_total < 100:
    print("Standard discount")
elif order_total < 10:
    print("Tiny order discount")
else:
    print("No discount")

What's wrong: every order under $10 is also under $100, so the broad order_total < 100 check always matches first. The elif order_total < 10: branch is dead code — it can never run, no matter what order_total is.

As shipped, this prints: Standard discount (wrong — an order of $5 should get the tiny-order discount)

Fix: check the narrower condition first — order_total < 10 before order_total < 100. Corrected output: Tiny order discount

Bug 6 — off-by-one at the boundary

# Goal: any speed of 60 or below (that's <= 60) counts as "Safe speed".
speed = 60
if speed < 60:
    print("Safe speed")
else:
    print("Too fast")

What's wrong: the goal says 60 or below should count as safe, which means the comparison needs <=. As written with plain <, a speed of exactly 60 falls into the wrong branch.

As shipped, this prints: Too fast (wrong — 60 should count as safe)

Fix: change < to <=. Corrected output: Safe speed

Bug 7 — comparing a string to a number

# Goal: print "Old enough" if age_text (typed in by a user, so it
# starts out as a string) represents an age of 18 or older.
age_text = "20"
if age_text >= 18:
    print("Old enough")
else:
    print("Not old enough")

Error type: TypeError. age_text is a string (remember: anything from input() is always a string, even if it looks like a number). Python won't compare a string to an integer with >= — it has no idea whether "20" should sort before or after the number 18, so it refuses and crashes instead.

Fix: convert first, with int(age_text) (this is the same int() you used back in Module 3): if int(age_text) >= 18:. Corrected output: Old enough

⚠️ Common mistake
Bugs 4, 5, and 6 are the sneakiest kind: Python never complains, the program runs top to bottom, and it prints a real, well-formed answer — it's just the wrong one. A crash at least tells you where to look. A silent logic bug only shows up when you (or someone else) compares the output against what it should have been, which is exactly why testing your conditions against more than one input matters.
