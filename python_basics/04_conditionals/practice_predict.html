Assignment 4 Practice: Predict the Output

⏱ Estimated time: 25 minutes Prerequisite: Assignment 4 — Making Decisions with Conditionals

Before you run a script, can you tell what it's going to print? This is one of the most useful skills a programmer builds — it's exactly what you'll do when a robot does something unexpected and you need to trace through the code in your head to find out why, before you ever plug it in.

What you'll practice
  • Tracing if / elif / else chains by hand, one condition at a time
  • Evaluating and, or, and not before checking your work
  • Remembering that elif stops at the first match, top to bottom
  • Spotting the difference a single boundary operator (< vs <=) can make

Prediction 1 — a basic if / else

temperature = 95
if temperature > 90:
    print("Too hot")
else:
    print("Temperature OK")

What prints? Too hot

Prediction 2 — a three-tier elif chain

speed = 45
if speed < 20:
    print("Slow")
elif speed < 60:
    print("Medium")
else:
    print("Fast")

What prints? Medium

Prediction 3 — combining with and

light_level = 30
is_daytime = light_level > 20 and light_level < 100
print(is_daytime)
if is_daytime:
    print("Cameras: normal mode")
else:
    print("Cameras: night mode")

What prints (two lines)? True then Cameras: normal mode

Prediction 4 — combining with or

button_a_pressed = False
button_b_pressed = True
should_move = button_a_pressed or button_b_pressed
print(should_move)
if should_move:
    print("Motors: engaged")
else:
    print("Motors: idle")

What prints (two lines)? True then Motors: engaged

Prediction 5 — flipping a boolean with not

print(not True)

What prints? False

Prediction 6 — first match wins

score = 95
if score >= 60:
    print("Pass")
elif score >= 90:
    print("Honors")
else:
    print("Fail")

Notice that score >= 90 would also be True if you checked it on its own. What prints? Pass

💡 Tip
Python checks an elif chain top to bottom and stops the instant it finds a True condition. It never goes back to check whether a later branch would also have matched. If you want the "Honors" case to actually be reachable, it needs to be checked before the broader "Pass" case.

Prediction 7 — one value, two operators

Same starting value, two separate snippets — only the comparison operator changes.

distance_cm = 20

# Snippet A
if distance_cm < 20:
    print("A: Too close")
else:
    print("A: Clear")

# Snippet B
if distance_cm <= 20:
    print("B: Too close")
else:
    print("B: Clear")

What prints from Snippet A? A: Clear
What prints from Snippet B? B: Too close

⚠️ Common mistake
< and <= only disagree at the exact boundary value — everywhere else they behave the same. That's exactly what makes boundary bugs sneaky: your code can pass every test you try, right up until someone hits the one number where < and <= disagree. Always ask: "should the boundary value itself count?"

Prediction 8 (Bonus — we haven't taught this, take a guess!)

Python has a shortcut that most languages don't. See if you can guess what it does before you run it.

x = 5
print(1 < x < 10)

What prints? True

This is called a chained comparison. 1 < x < 10 means exactly what it looks like it means in math class: "is x between 1 and 10?" Python quietly evaluates this as 1 < x and x < 10. It's not required — the and version works everywhere and is a perfectly good habit to keep — but you'll see the chained version in other people's code, so it's worth recognizing.

Check Yourself
