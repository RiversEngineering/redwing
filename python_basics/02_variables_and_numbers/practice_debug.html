Assignment 2 Practice: Debug It

⏱ Estimated time: 30 minutes Prerequisite: Assignment 2 — Variables & Numbers

practice_debug.py contains 7 bugs. Some of them would crash the program, so those are shipped fully commented out — you'll need to read the code and reason about what error it would raise before you uncomment and fix it. The rest are live: they run without crashing, but print the wrong answer. Your job is to find each bug and fix it so the output matches what's described below.

What you'll practice
  • Recognizing NameError, SyntaxError, and ZeroDivisionError
  • Spotting a precedence bug that produces a wrong-but-plausible number
  • Spotting a stale-value bug caused by += being in the wrong place
  • Spotting a shadowing/reassignment mistake
💡 Tip: read the traceback from the bottom up
When Python crashes, the last line of the traceback tells you the error type and message — start there. The lines above it show you the path the program took to get there, with the line number of the crash listed last. For logic bugs (no crash, just a wrong number), there's no traceback to help you — you have to trace the variables by hand, the same way you did in Predict the Output.

Bug 1 — NameError

# score = 95
# print(scroe)

Intended: store a robot's test score and print it. If uncommented as written, this raises a NameError — scroe was never defined. Expected output once fixed:

95

Bug 2 — precedence

a = 90
b = 80
c = 100
average = a + b + c / 3
print("Average:", average)

Intended: compute the average of three scores (90, 80, 100). This bug doesn't crash — it runs live and currently prints Average: 203.33333333333334, which is way too high for an average of these three scores. Expected output once fixed:

Average: 90.0

Bug 3 — SyntaxError

# 1st_place = 1
# print(1st_place)

Intended: store a robot's finishing place and print it. If uncommented as written, this raises a SyntaxError — variable names can't start with a digit. Expected output once fixed:

1

Bug 4 — stale value

speed = 20
print("Speed:", speed)
speed += 10

Intended: increase the robot's speed by 10, then print the new speed. This bug doesn't crash — it runs live and currently prints Speed: 20, the value before the increase, because the print() runs before the +=. Expected output once fixed:

Speed: 30

Bug 5 — ZeroDivisionError

# reading_total = 10 + 20 + 30
# reading_count = 0
# average_reading = reading_total / reading_count
# print(average_reading)

Intended: compute the average of three sensor readings (10, 20, 30). If uncommented as written, this raises a ZeroDivisionError — reading_count doesn't match how many readings were actually added up. Expected output once fixed:

20.0

Bug 6 — wrong constant

celsius = 20
fahrenheit = celsius * 9 / 4 + 32
print("Fahrenheit:", fahrenheit)

Intended: convert 20°C to Fahrenheit using the formula F = C * 9 / 5 + 32. This bug doesn't crash — it runs live and currently prints Fahrenheit: 77.0, which looks plausible but is wrong because the fraction uses the wrong denominator. Expected output once fixed:

Fahrenheit: 68.0

Bug 7 — shadowing / reassignment

cruising_speed = 30
cruising_speed = cruising_speed - 30
print("Cruising speed:", cruising_speed)

Intended: print the robot's cruising speed, which should still be 30. This bug doesn't crash — it runs live and currently prints Cruising speed: 0, because a second line overwrites cruising_speed with a temporary checkpoint-stopped value instead of storing that value under its own name. Expected output once fixed:

Cruising speed: 30
